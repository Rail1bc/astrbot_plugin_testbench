> [!WARNING]
> **虚拟会话是真实会话，请谨慎使用**
>
> 虚拟会话经插件页面直连 AstrBot 事件总线，进入与真实平台消息相同的处理管道——其他插件（主动回复、定时任务、记忆、知识库等）会把它们当作真实用户消费，可能产生长期数据遗留：
>
> - **工具会真实执行**：绑定启用计算机工具（computer use、网页搜索、知识库检索、cron 工具）的配置档案后，虚拟会话可真实执行代码 / shell / 浏览器操作，影响宿主机；管理员身份发送的消息可触发需管理员权限的工具。
> - **异步与定时任务可能命中**：插件内的异步补发（fire-and-forget）与定时任务（cron）可能命中虚拟会话，在管道结束后继续发送回复或产生副作用。
> - **删除不会清理第三方数据**：删除虚拟会话只会清理本插件自身的数据；其他插件以该会话为键写入的长期数据（对话历史、记忆、定时任务等）不会随之删除，会残留为孤立数据。

## 适用场景

- **快速上手**：改了提示词、换了插件配置或试不同模型，却只能凭感觉判断好坏——同一条消息并发发送到多个虚拟会话，回复并排对比，差异一眼可见。
- **进阶使用**：用测试集编排复杂测试（批量段、机械 + LLM 断言、any / not 组合、跨轮最终断言），验证已有配置在极端场景（并发、边界输入、多轮追问）下是否稳定可靠。
- **不推荐插件开发者调试自己的插件**：虚拟链路经插件页面直连事件总线、不经过真实平台适配器，与真实链路存在差异，可能产生不可预料的差别——调试插件请用真实平台消息。

## 一套完整的测试系统

| 组织 | 观察 | 评审 |
| :--- | :--- | :--- |
| **测试组模型**<br>组共享一套配置（平台 / 档案 / 发送者 / 消息类型），组内会话可单独覆盖，测试以组为单位开展。 | **并行会话面板**<br>同时打开多个面板并排查看，支持拖拽排序、置顶与按轮次对齐阅读。 | **机械 + LLM 断言**<br>正则 / 包含 / 格式等机械规则，加可复用的 LLM 评审 Profile。 |
| **群聊消息与自动@**<br>虚拟会话可设为群聊消息类型，唤醒只监听群消息的插件；不 @ 时验证 filter 唤醒。 | **在途实时状态**<br>每条消息「已入队 / 排队等待 LLM / LLM 生成中 / 完成」四阶段实时可见。 | **any / not 组合断言**<br>嵌套任意组与取反，表达复杂通过条件。 |
| **身份与虚拟群聊**<br>跨测试组共享的发送者身份与群成员池，消息可按身份（含管理员）发送。 | **消息流视图**<br>与 LLM 历史并行的收发记录；历史可 JSON 编辑与重新生成。 | **报告 3 类 + 重试**<br>统计 / 详情 / LLM 生成报告三类组织，评审失败可一键重跑。 |

## 三步开始

1. 从 AstrBot 插件市场安装，或从 [Release](https://github.com/Rail1bc/astrbot_plugin_testbench/releases) 下载 zip 在「插件」页安装并启用。
2. 重载 AstrBot，进入「会话测试台」页面，新建一个测试组。
3. 打开一个会话，输入一句话发送——消息走真实管道，回复实时回到面板。

| 配置项 | 用途 |
| :--- | :--- |
| 平台来源 | 虚拟消息的平台来源，默认 `webchat`（与 WebUI 一致）。 |
| 配置档案 | 可选绑定 AstrBot 配置档案，精确路由到该档案；留空用默认配置。 |
| 发送身份 | 发送者 id / 昵称，或选用跨组共享的测试身份；留空为 `testbench` / 测试台。 |

群聊消息类型的会话需借助「自动@」或 filter（如 Heartflow）唤醒；测试身份与虚拟群聊在左侧「身份与群聊」视图管理。

## 功能详解

### 虚拟会话：一条消息，多份回复并排看

消息通过框架原生插件页面注入 AstrBot 事件总线，走与真实平台消息相同的核心处理管道：唤醒检查 → 白名单 → 会话状态 → 限流 → 内容安全 → 预处理 → 插件与 LLM 处理 → 回复装饰——测试的是真实环境下的提示词、配置与模型行为。（注：虚拟链路不经过真实平台适配器，与真实链路存在差异，不推荐用它调试自己的插件，见「适用场景」。）

### 并发测试

一条消息同时发送给所有已打开的会话，每个会话窗口**独立实时刷新**——谁完成谁更新，无需等待整批结束；不设总超时、不额外分批。**群发不阻止重叠发送**：agent 处理上一条消息时可再次群发，覆盖真实「重复追问」场景。

### 面板与统计

每个面板展示状态（成功 / 无回复 / 错误，无回复时区分「未唤醒」与「已唤醒但无回复」）、回复、耗时与 min / max / avg / p50 / p95 统计；底部在途消息条实时显示每条消息「已入队 / 排队等待 LLM / LLM 生成中 / 完成」四个阶段，完成后自动刷入会话历史。

### 对话历史

每个面板展示完整对话历史（含推理内容与工具调用），带思维链的回复默认折叠、可展开查看；支持一键重置，或在 JSON 编辑器中整体编辑结构（编辑单条 / 新增 / 删除对话），也可对单条用户发言「重新生成」——截断该轮及之后的历史重新走管道。

### 群聊消息与唤醒

测试组 / 会话可设为群聊消息类型（GroupMessage），使只监听群消息的插件（如 Heartflow 主动回复插件）可被虚拟会话触发；发送时可选择「自动@机器人」直接唤醒，或关闭以未唤醒状态进管道、只能被 filter 通过唤醒。唤醒状态与原因（未唤醒 / 已唤醒但无回复）在结果摘要与面板中可见。

### 测试身份与虚拟群聊

「身份与群聊」视图集中管理**跨测试组共享**的测试身份（发送者实体，可标记管理员）与虚拟群聊（成员池）；群聊会话可绑定虚拟群聊作为群成员来源，群发栏与测试集消息也可按身份发送。管理员身份发送的消息可触发需管理员权限的工具。

### 消息流视图

每个会话面板可切换「LLM 历史 ↔ 消息流」——消息流是与 LLM 历史并行的纯记录（不注入 LLM 上下文），还原真实消息收发过程与回复状态（成功 / 无回复 / 错误）。

### 测试集与评审

测试集以消息序列 + 批量段组织，可配置发送身份与自动@；每条消息可带**机械规则**（正则 / 包含 / 格式等）与 **LLM 评审**（可复用 Profile、any / not 组合、跨轮最终断言）。运行结束后可生成持久化报告，按统计 / 详情 / LLM 生成报告三类查看，评审失败可一键重跑。

### 会话管理

测试组与虚拟会话持久化存储；支持同组克隆（复制历史新建 N 个一致会话）与基于历史衍生全新测试组；旧版平铺会话数据自动迁移。

## 使用流程

1. **创建测试组**：在左侧列表点击「＋ 新建测试组」即直接创建一个 0 会话的默认配置测试组（不弹编辑弹窗）；按需点击组行 ✎ 编辑，在弹窗中设置组名称、会话数量、平台来源与配置档案（可选发送者信息、消息类型与绑定虚拟群聊），保存后组内自动生成相应数量的虚拟会话（均继承组配置）。
2. **管理组内会话**：展开测试组可看到组内会话列表；点击「添加」随时为组新增会话，或删除组内单个会话、整个测试组。点击会话行头部展开配置，逐项查看有效值与「已修改 / 继承组」状态，点击「编辑配置」可单独覆盖该会话的平台 / 配置档案 / 发送者信息 / 消息类型（留空恢复继承组配置）。
3. **打开 / 切换会话**：点击会话「打开」在右侧并行查看；再次点击「关闭」收起。面板头部可拖拽排序，或点击「置顶」固定在前面。面板页头的视图切换按钮可在「LLM 历史 ↔ 消息流」间切换展示。
4. **发送消息**：在单个面板底部输入框发送消息到该会话；或在工作区下方群发栏输入一条消息，点击「发送到全部」并发发送给所有已打开的会话（群发栏可选发送身份与是否自动@）。
5. **查看结果**：每个面板展示状态与对话历史更新；群发时每个会话窗口**独立刷新**——谁完成谁更新，无需等待整批结束；全部完成后顶部汇总成功 / 无回复 / 错误计数与 min / avg / p95 耗时统计。

## 开发者

> **开发流程**：本地不跑测试，修改直接提交推送到 `dev` 分支，由 GitHub Actions 自动把关——push 到 dev 触发 `pytest.yml`（320 个测试函数 + 前端 JS 检查：node --check 语法检查与 node:test 纯函数动态测试）与 `ruff-format.yml`；dev 验证通过后合并到 `main`，metadata.yaml 变更即触发 release.yml 自动发版。以下本地命令仅在主动排查时使用。

```bash
# 单元测试（测试随插件仓库维护，位于 data/plugins/astrbot_plugin_testbench/tests/）
.venv/Scripts/python.exe -m pytest data/plugins/astrbot_plugin_testbench/tests/ -q

# 代码质量检查
.venv/Scripts/python.exe -m ruff check data/plugins/astrbot_plugin_testbench/tests/
.venv/Scripts/python.exe -m ruff format --check data/plugins/astrbot_plugin_testbench/tests/
```

Windows 开发者可直接运行 `run_ruff.bat` 进行格式化与质量检查。
